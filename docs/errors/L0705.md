# L0705: lust cannot prove this dyn lifetime bound

<!-- rustc-wrong: pass -->

A `'static` object bound (`dyn Trait + 'static`, or the default
under `&'static dyn Trait`) needs the concrete type to live for
`'static`. When the value holds only references and `dyn` values,
the borrow checker proves that. lust rejects the coercion instead of
guessing when it cannot: for a type parameter without a `'static`
bound, and for a `&'static dyn Trait` filled by anything but a shared
borrow of a place (a static, a local, a field, a deref: the borrow
checker then proves its lifetime, as for any `&'static T`) or a value
already typed `&'static dyn Trait`.
Rust accepts the wrong example, because it promotes the constant
expression `&S { n: 5 }` to a `'static` value; lust does not. Borrow a
`static` item, or drop the `'static` bound.

The same holds for uses that need a `dyn` value to be `'static`:
a method of `impl dyn Trait` or of `impl Other for dyn Trait` (an
impl header's `dyn Trait` means `dyn Trait + 'static`), a coercion
to `dyn Trait + 'static`, and a call through `dyn` to a method with
`where Self: 'static`. lust accepts these only in a body where no
`dyn` value can come from a shorter lifetime: no `&dyn Trait`
parameter, no call that returns `&dyn Trait`, and no `dyn` value
made from a type that holds a borrow. Rust infers each lifetime
separately, so it accepts some bodies lust rejects. Write
`impl dyn Trait + '_` for an impl that takes any lifetime. A trait
bounded by `'static` (`trait Trait: 'static`) makes every
`dyn Trait` `'static`, as in Rust, so its uses need no proof.

The check covers object lifetimes inside other types too
(`Vec<&dyn Trait>` to `Vec<&(dyn Trait + 'static)>`). Under `&mut`,
`*mut`, a fn pointer, or a struct or enum of your own (lust computes
no variance for them), the object lifetimes must match: lust cannot
prove that a shorter one equals `'static`, or the reverse. In a body
whose return type holds `&mut dyn Trait` inside another type, a
`'static` use has no proof either, because a value there takes the
caller's lifetime.

lust keeps the lifetime of a reference to a `dyn` value only when
it is a written `&'static dyn Trait`. A `X: 'static` bound (on a fn,
impl, or struct parameter) holds for a `dyn` type with a `'static`
object lifetime or one written in a body (Rust infers it there, and
the borrow checker proves the bound), and for a reference to one only
when it is `&'static`.

## Wrong

```rust
trait T {
    fn read(&self) -> u32;
}

struct S {
    n: u32,
}

impl T for S {
    fn read(&self) -> u32 {
        self.n
    }
}

fn main() {
    let d: &'static dyn T = &S { n: 5 };
    println!("{}", d.read());
}
```

## Fixed

```rust
trait T {
    fn read(&self) -> u32;
}

struct S {
    n: u32,
}

impl T for S {
    fn read(&self) -> u32 {
        self.n
    }
}

static S0: S = S { n: 5 };

fn main() {
    let d: &'static dyn T = &S0;
    println!("{}", d.read());
}
```
