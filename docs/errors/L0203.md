# L0203: lifetime name or form not supported

<!-- rustc-wrong: pass -->

Two cases share this code. A lifetime name that the item does not
declare is an error in Rust too (E0261). The other case is a lifetime
form that lust does not check yet, so it rejects the program instead of
accepting a borrow rustc might reject: a named lifetime in a fn pointer
type outside fn signatures and `let` annotations (a struct field, an
alias), two of them in one fn pointer type, or one inside a nested fn
pointer or `dyn` type; a `for<..>` binder on `Fn` sugar or `dyn Fn` that
elision cannot express (a plain fn pointer type may write one, up to 16
region places), or with a lifetime of the enclosing item next to it;
named lifetimes in a `dyn` type's trait arguments (`&'static` there
works); an explicit lifetime in a body type
other than a `let` annotation on names, an elided lifetime argument of a
trait with lifetime params, lifetime arguments in a trait's own bounds,
associated types in a trait with lifetime params, `T: 'a` bounds on
named lifetimes outside fns and inherent methods, and a fn's `T: 'a`
bound that a call cannot prove (a caller's type param with no matching
bound, or a fn with such a bound used as a value). Rust accepts the
wrong example; lust
does not yet. Elide the lifetime, or use a generic `F: Fn(&T)` param.

## Wrong

```rust
struct Hooks<'a> {
    len: fn(&'a str) -> usize,
}

fn len(s: &str) -> usize {
    s.len()
}

fn main() {
    let h = Hooks { len };
    println!("{}", (h.len)("abc"));
}
```

## Fixed

```rust
struct Hooks {
    len: fn(&str) -> usize,
}

fn len(s: &str) -> usize {
    s.len()
}

fn main() {
    let h = Hooks { len };
    println!("{}", (h.len)("abc"));
}
```
